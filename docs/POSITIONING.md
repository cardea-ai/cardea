# Cardea 포지셔닝

상태: 확정 (2026-10-25, `docs/requirements.md` 1장 "최종 방향 결정"에서 Build 지속
조건부로 확정). 변경 이력은 `docs/history/POSITIONING.md`에서 관리한다.
`docs/COMPETITIVE_ANALYSIS.md`의 경쟁 분석을 근거로 확정했다. 전략이 바뀌면 이 문서를
먼저 고치고, `docs/requirements.md` 1장과 메시지 자료를 따라 맞춘다.

## 한 줄 포지셔닝

Cardea는 PII 탐지 솔루션이 아니다. **민감정보를 AI 모델에 원문으로 절대 넘기지 않는다는
보안 원칙**을 코어에 두고, 사람의 채팅과 에이전트의 툴 호출을 하나의 정책 엔진으로
통제하는 오픈코어 게이트웨이다.

핵심 차별점은 탐지 정확도가 아니다. 2차 경쟁력 분석(`docs/COMPETITIVE_ANALYSIS.md` 5장,
Skyflow/Protecto/Limina/Nightfall AI/NoPII 비교) 결과, "모델 비도달 보장" 자체와
"에이전트 메모리에 PII를 안 남긴다"는 이미 해외 경쟁사(Skyflow)가 공개적으로 쓰는
메시지라 더 좁혀야 한다. 좁힌 차별점은 세 가지의 교집합이다.

1. **오픈코어·로컬 우선·클라우드 비의존** — Skyflow·Protecto·Nightfall은 SaaS/호스팅
   볼트가 기본이고, NoPII는 클라우드 프록시 전용이다. 자체 호스팅 바이너리를 무료로
   영구 쓸 수 있는 곳은 다섯 경쟁사 중 없다.
2. **사람 채팅 + 에이전트 툴 호출을 하나의 정책 엔진으로 통제** — Nightfall은 콘텐츠
   검사(Inference Hooks)와 툴 거버넌스(MCP Gateway)를 4개의 분리된 표면으로 나눠
   운영하고, 공식 문서에 "MCP Gateway는 프롬프트를 스캔하지 않는다"고 명시한다.
   Skyflow·Protecto는 에이전트/MCP 중심이라 사람의 일반 채팅 게이트웨이 역할이 약하다.
3. **에이전트 거버넌스(세션 오염 추적 AG-04 등)** — 메모리 보호 자체(AG-06)는 더는
   단독 차별점이 아니므로, "메모리에 쌓인 뒤 오염된 세션이 이후 행동에 영향을 주는
   흐름을 추적·차단"하는 쪽으로 구체화해야 차별점이 유지된다.

탐지율·속도 숫자로 경쟁사와 싸우지 않는다. 또한 FR-AC-03(break-glass)은 Protecto의
CBAC(역할+작업+컨텍스트 기반 동적 재식별)보다 뒤처진 설계라는 격차가 확인됐다 —
사업화 전 명세 보완이 필요하다(`docs/COMPETITIVE_ANALYSIS.md` 6장 후속 조치 참고).

> 변경 사유: 한국 규제(N2SF·ISMS-P) 대응을 전략의 중심축으로 두면 포지셔닝이 지역에
> 묶인다. 그래서 "민감정보는 모델에 도달하기 전에 반드시 가로채 마스킹/차단한다"는
> 보편적 보안 원칙을 1번 기둥으로 올리고, 한국 민감정보 탐지는 그 원칙을 구현하는
> **첫 번째 로케일 룰팩**으로 내린다. 아키텍처는 이미 이렇게 설계돼 있다(ADR-0002:
> 로케일별 탐지도 코어에 내장하지 않고 플러그인). 전략 메시지만 이 설계를 따라가도록
> 바꾸는 것이다.
> 규제 증적(N2SF/ISMS-P/GDPR/HIPAA 등)은 "로케일별 선택 모듈"로 남기고, 핵심 가치
> 제안에서는 뺀다.

## 목표 고객 우선순위

경쟁사(Corepin, GenAI Shield, Airgap Studio 등 국내)의 공통된 약점은 "사람의 프롬프트"
시대 제품이라는 점이다. 해외 경쟁사(Skyflow, Protecto)는 이미 에이전트/MCP를 다루지만
오픈코어·자체 호스팅이 아니라 SaaS·호스팅 볼트가 기본이다(`docs/COMPETITIVE_ANALYSIS.md`
5장). 에이전트(코딩 에이전트, MCP 툴 호출, 상주형 에이전트)를 실제로 도입하려는 조직은
지금 보안팀이 막고 있거나 임시로 허용해둔 상태다. 이 틈이 ICP다.

1. 1차 타깃: 개발팀이 이미 코딩 에이전트를 쓰는데 보안팀이 "일단 금지"로 대응한 조직
   (국가·업종 무관, 공통 사유는 "민감정보가 외부 모델로 나갈까 봐 막았다").
2. 2차 타깃: 민감정보 유출이 법적·사업적으로 치명적인 규제 산업(금융, 헬스케어, 법률 등).
   국내는 N2SF·ISMS-P, 해외는 GDPR·HIPAA 같은 각 지역 규제를 "같은 코어 원칙의 로케일
   증적"으로 붙인다 — 지역을 먼저 고르고 시작하지 않는다.

둘 다 "탐지 API 판매"로는 닿지 못하고, "모델에 안 보낸다는 보장 + 에이전트 거버넌스"가
묶여야 풀리는 영역이다.

## 페르소나별 메시지 (한 문장으로 전부 설명하려 하지 않는다)

| 대상 | 메시지 |
|---|---|
| 개발자 (PLG 진입점) | 설치 5분, Claude Code·Kiro·Hermes 등에 바로 연결, 무료로 영구 사용. 보안팀 승인 없이 먼저 쓸 수 있다는 게 메시지 |
| 보안·컴플라이언스팀 | 이미 개발자들이 쓰고 있는 그 도구를, 조직 정책·감사·N2SF 증적 아래로 가져온다 — 금지가 아니라 가시화·통제 |
| 인프라팀 | 오픈소스 코어, 클라우드 비의존, 폐쇄망 지원 — 벤더 종속 없음 |

진입 순서: 개발자 침투 → 보안팀이 뒤늦게 발견 → "이미 쓰고 있으니 통제만 하자"로 전환.
이 역방향 진입로가 오픈코어 PLG의 실제 무기이며, 톱다운 B2B 모델인 국내 경쟁사에는 없다.

## 증거를 쌓는 순서

1. NFR-DQ 평가셋으로 Corepin·Airgap Studio와 동등 조건 벤치마크 — "탐지는 기본, 그 위가
   다르다"는 주장이 거짓말이 안 되도록 최소 동등성을 먼저 확인한다.
2. 경쟁사 중 아무도 없는 데모를 먼저 만든다. "메모리에 PII를 안 남긴다"(Skyflow가 이미
   공개적으로 주장)가 아니라, **오픈소스 자체 호스팅 상태에서 사람 채팅과 에이전트 툴
   호출을 하나의 정책 엔진으로 통제하면서, 오염된 세션(AG-04)이 메모리에 쌓인 뒤 다음
   행동에 영향을 주는 흐름까지 추적·차단**하는 장면을 데모로 만든다. 탐지 데모가
   아니라 "통합 정책 엔진 + 세션 오염 추적" 데모가 차별화 증거다.
3. GitHub 공개 + 오픈소스 커뮤니티 — 보안 게이트웨이 카테고리의 신뢰는 폐쇄형 SaaS보다
   오픈소스가 더 빨리 쌓인다.
4. 공공·금융 PoC 1건 — N2SF 대응을 "표에만 있는 주장"이 아니라 "실제 통과 사례"로
   바꾼다.
5. FR-AC-03(break-glass)을 Protecto의 CBAC(역할+작업+컨텍스트 기반 동적 재식별) 수준으로
   보완한 뒤에만 "역할 기반 재식별"을 세일즈 메시지에 쓴다 — 지금 설계로는 격차가 있다.

## 하지 말아야 할 것

- 탐지율·속도 숫자로 광고하지 않는다. 더 높은 숫자를 주장하는 경쟁사가 이미 있고, 검증
  안 된 숫자 전쟁은 신뢰를 깎는다.
- "모든 기능을 다 가진 올인원"으로 소개하지 않는다. 개발자에게는 무겁게, 보안팀에게는
  산만하게 들린다. 페르소나별로 다른 한 문장을 쓴다.
- 한국 규제(N2SF·ISMS-P) 대응을 1번 메시지로 쓰지 않는다. 핵심 메시지는 "민감정보는
  모델에 도달하기 전에 반드시 차단/마스킹한다"는 로케일 무관 보안 원칙이고, 한국 규제는
  그 원칙의 한 증적일 뿐이다 — "한국형"이라는 표현은 어떤 언어의 자료에서도 쓰지 않는다.
- "에이전트 메모리에 PII를 안 남긴다"를 단독 차별점으로 광고하지 않는다. Skyflow가 이미
  같은 메시지를 공개적으로 쓴다(`docs/COMPETITIVE_ANALYSIS.md` 5장 참고). 차별점은
  "오픈코어+통합 정책 엔진+세션 오염 추적"의 결합으로만 말한다.
- FR-AC-03 설계는 CBAC급(역할+작업+컨텍스트 기반 동적 재식별)으로 다시 썼다
  (`docs/requirements.md` 3장 보완). 하지만 **구현·벤치마크 전까지는** "역할 기반
  재식별"·"CBAC"를 경쟁 우위로 광고하지 않는다 — 설계 문서와 실제 동작은 다르다.
