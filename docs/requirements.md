# Cardea 요구사항 명세

Cardea는 AI 모델과 AI 에이전트 앞단에서 개인정보·민감정보가 외부로 유출되지 않도록 보호하는 글로벌 표준 보안 AI 게이트웨이다. 이 문서는 Cardea가 무엇을 해야 하는지 정의하는 요구사항의 원본이다.

상태: 초안. 변경 이력은 `docs/history/requirements.md`에서 관리한다.
이전 이름: waiy

## 표기

| 표기 | 의미 |
|---|---|
| P0 | 필수. 첫 상용 릴리스 전 충족 |
| P1 | 우선 도입. 상용 1년 차 내 |
| P2 | 검토 후 도입 |
| 무료 / 유료 / 공통 | 기능이 열리는 라이선스 티어. 기준은 6장 티어 매트릭스 |
| 제안값 | 측정 후 확정할 수치 |

별도 표시가 없는 FR은 P0이다.

## 추적 규칙

- 이슈: 요구사항 ID당 GitHub 이슈 하나. 라벨은 `priority/P0`, `tier/free`, `area/detection` 형식.
- PR: 본문에 `Implements FR-PI-01`처럼 ID를 적는다.
- 테스트: 테스트 이름에 ID를 넣는다(예: `TestFR_PI_01_ResidentNumberChecksum`). CI가 ID별 테스트 유무로 추적표를 만든다.

## 용어

| 용어 | 정의 |
|---|---|
| 민감도 등급 | 요청·데이터에 붙는 보호 수준. 공개·내부·기밀·극비 4단계 |
| 스코프 | 메모리·정책·데이터가 속한 범위. 조직·팀·프로젝트·개인 |
| 가역 마스킹 | 원문을 토큰으로 바꿔 보내고 응답에서 원문으로 되돌리는 처리 |
| 토큰 금고 | 가역 마스킹의 원문과 토큰 대응표를 보관하는 암호화 저장소 |
| break-glass | 평소 금지된 원문 열람을 승인을 거쳐 예외로 허용하는 절차 |
| ZDR | 프로바이더가 요청 데이터를 보관하지 않고 학습에 쓰지 않는 조건(Zero Data Retention) |
| 세션 오염 | 세션이 민감 데이터나 신뢰할 수 없는 콘텐츠를 읽은 상태. 이후 행동의 위험도를 높인다 |
| 룰팩 | 탐지 규칙·사전·모델을 묶어 서명 배포하는 업데이트 단위 |
| 플러그인 슬롯 | 판정 파이프라인에서 플러그인이 끼워지는 자리. 정규화기·탐지기·분류기·정책·처리기·연동 |
| 섀도 AI | 게이트웨이를 거치지 않는 AI 서비스·에이전트 사용 |
| 키 폐기 삭제 | 데이터를 사용자별 키로 암호화하고 키를 폐기해 삭제를 대신하는 방식(crypto-shredding) |
| 지표 대시보드 | 비용·보안·효율성 3대 카테고리의 운영 지표를 모아 보여주는 리포트 화면 (PL-06) |

## 1장 보완 — 포지셔닝과 핵심 차별점 (개정)

근거: `docs/COMPETITIVE_ANALYSIS.md` (경쟁 분석) → `docs/POSITIONING.md` (포지셔닝 전문).

Cardea의 핵심 차별점은 **민감정보 탐지 정확도가 아니다.** 국내에 이미 Corepin,
GenAI Shield, Airgap Studio 같은 한국 민감정보 탐지·마스킹 제품이 출시돼 있고, 일부는
99%대 탐지율과 공공 인증까지 확보했다. 탐지율·속도 숫자로 이들과 경쟁하지 않는다.

**한국 규제(N2SF·ISMS-P) 대응도 핵심 가치 제안의 1번 기둥으로 쓰지 않는다.** 지역
규제를 전략의 중심에 두면 포지셔닝이 지역에 묶인다. 대신 **"민감정보는 AI 모델에
도달하기 전에 반드시 가로채 마스킹/차단한다"는 로케일 무관의 보편적 보안 원칙**을
코어 가치 제안으로 둔다. 한국 민감정보 탐지·N2SF/ISMS-P 증적은 이 원칙을 구현하는
**첫 번째 로케일 룰팩/증적 모듈**이며, 같은 구조로 GDPR·HIPAA 같은 해외 로케일 모듈을
나중에 추가할 수 있다(이미 ADR-0002가 로케일별 탐지를 코어 내장이 아닌 플러그인으로
설계해 둬서, 이 전환에 아키텍처 변경은 필요 없다 — 전략 메시지만 설계를 따라간다).

Cardea가 실제로 파는 것은 **모델 비도달 보장(코어 보안 원칙) + 에이전트 거버넌스 +
오픈코어 PLG**의 교집합이다. 이 세 가지를 동시에 하는 제품은 (2026-10 기준 조사로는)
없다:
- 국내 PII 경쟁사들은 "탐지 API 판매"에 머물러 있고 에이전트/MCP 거버넌스(AG-01~12)를
  다루지 않는다.
- 해외 범용 게이트웨이(LiteLLM, Portkey 등)는 가드레일을 붙일 수는 있지만, "민감정보가
  모델에 도달하지 않는다"를 기본값·코어 보안 원칙으로 못 박지는 않는다.
- 둘 다 톱다운 B2B 판매 모델이라, Cardea의 "무료 개인 도구로 먼저 침투 → 조직이 뒤늦게
  발견하고 통제로 전환"하는 오픈코어 PLG 진입로가 없다.

그러므로 FR-PI(탐지)는 "기본값으로 갖춰야 할 비용"이고, 사업 판단과 로드맵 우선순위는
AG(에이전트 대응)·FR-PI-04/FR-TK-05(가역 마스킹·토큰 금고 같은 모델 비도달 보장 장치)·
오픈코어 유통 구조 쪽에 둔다. 한국 규제 대응(N2SF 대응표, FR-RT-06 등)은 "로케일별
선택 모듈"로 유지하되 핵심 메시지에서는 뺀다. 신규 기능을 검토할 때 "이게 탐지 정확도
경쟁인가, 모델 비도달 보장·에이전트 거버넌스 경쟁인가"를 먼저 구분한다.

## 1장 보완 — 최종 방향 결정 (확정)

`docs/COMPETITIVE_ANALYSIS.md`(2차 경쟁력 분석, OSS 적극 채택 재검토)와
`docs/GETTING_STARTED.md`(온보딩 UX 드래프트) 검토를 거쳐 사용자가 최종 방향을
확정했다. 결론: **Build 지속 (조건부)** — Buy/조합 전환이나 스코프 폐기가 아니라,
아래 네 조건으로 범위를 좁힌 Build다.

1. **자체 개발 범위는 OSS 조합(ADR-0007)의 접합부로 한정한다.** 탐지 엔진(Presidio)·
   토큰 금고 크립토(OpenBao)·자가 탐지(gitleaks)·서명/SBOM(cosign+syft/grype)·MCP
   1차 allowlist(Bifrost core)는 조립하고, Cardea가 직접 만드는 건 로케일별 탐지
   플러그인(한국 민감정보 유형 포함)·가역 마스킹 세션 스코프 매핑·사람 채팅+에이전트
   툴 호출 통합 정책 오케스트레이션뿐이다.
2. **핵심 가로채기 메커니즘은 표준 프로토콜(LLM API, MCP) 프록시로 확정한다
   (ADR-0008).** 도구별 훅 연동은 보조 장치로만 쓴다 — 이게 "모델 비도달 보장"을
   닫힌 집합으로 증명할 수 있는 유일한 방식이기 때문이다.
3. **포지셔닝은 로케일 무관의 글로벌 표준으로 확정한다.** "한국형"이라는 표현은
   Cardea 자신의 기능·브랜드 설명에서 전부 뺐다(어떤 언어의 자료에서도). 핵심 가치
   제안은 "개인정보·민감정보가 외부로 유출되지 않는다는 글로벌 표준 + 사람 채팅과
   에이전트 툴 호출을 하나의 정책 엔진으로 통제 + 오픈코어 PLG"의 교집합이고, 한국
   민감정보 탐지·N2SF/ISMS-P는 그 원칙의 첫 번째 로케일 룰팩일 뿐이다.
4. **사업화 전 선행 조건은 그대로 유효하다** — (a) NFR-DQ-02 한국어 평가셋으로
   Corepin/Airgap Studio와 동등 조건 벤치마크, (b) FR-AC-03(break-glass)을
   Protecto의 CBAC급(역할+작업+컨텍스트 기반 동적 재식별)으로 보완, (c)
   `docs/GETTING_STARTED.md`에서 확정한 온보딩 흐름(특히 `cardea quickstart` 원스텝
   경로)을 실제 수용 기준에 반영. 이 세 가지가 끝나기 전에는 탐지 정확도나 한국
   규제 대응을 세일즈 메시지로 쓰지 않는다.

## 2장 보완 — 라이선스별 관리 방법: 리포트 항목 갱신

"리포트" 관리 항목을 비용·보안·효율성 3개 카테고리로 나누고, 무료는 각 카테고리의 일부
지표만 노출한다. 전체 항목은 `docs/EDITIONS.md`의 "지표 대시보드" 절을 따른다.

| 관리 항목 | 무료(개인) | 유료(엔터프라이즈) |
|---|---|---|
| 리포트 — 비용 | 본인 토큰·API 사용량, 모델별 추정 비용 | 부서·팀·프로젝트별 비용 배분(차지백), 예산 대비 소진율, 모델/라우팅 비용 비교 |
| 리포트 — 보안 | 본인 탐지·차단 건수(유형별 합계만) | 등급별/유형별 탐지 현황, 오탐률, 우회 트래픽 현황, ISMS-P 증적 리포트, SIEM 전달 상태 |
| 리포트 — 효율성 | 캐시 히트율, 토큰 절감량(개인) | 캐시 히트율(팀 공유 포함), 토큰 절감량, 게이트웨이 지연(p95), 가용성·장애 전환 현황 |

## 3장 보완 — FR-PI-04 (가역 마스킹 토큰 설계)

FR-PI-04 수용 기준에 토큰 형식·스코프·금고 설계를 구체화한다.

| 항목 | 규칙 |
|---|---|
| 토큰 형식 | `⟦TYPE_난수⟧` (예: `⟦RRN_8f2a1c⟧`). 타입 뒤 난수는 CSPRNG로 만든 base62 6~8자. 순번(`_1`,`_2`)은 쓰지 않는다 — 순번은 탐지 건수·순서를 토큰 자체에서 노출시킨다 |
| 매핑 | 결정론적 해시 금지. 난수 토큰 ↔ 원문은 암호화된 토큰 금고에서만 연결한다(원문 역산 방지) |
| 참조 일관성(coreference) | 같은 세션/요청 스코프 안에서는 동일 원문 → 동일 토큰. 세션이 끝나면 토큰은 폐기한다. 세션을 넘는 전역 고정 토큰은 재식별(linkage) 위험이 있으므로 쓰지 않는다 |
| 조직 스코프 엔티티 해석 | 세션을 넘는 동일 엔티티 추적이 필요하면(FR-MEM 팀 메모리) 별도 ACL·사유 기록을 거는 엔티티 해석 계층으로 분리하고 토큰 발급 로직과 섞지 않는다 |
| 형태보존 옵션 | 소스코드·DB 커넥션 문자열처럼 모델이 형태를 유지해야 하는 맥락(FR-PI-06)에서는 같은 포맷의 합성 더미 값을 처리기 플러그인이 대신 넣을 수 있다. 더미 여부는 메타데이터로 태깅하고, 원문 복원 시점에만 실제 값으로 치환한다 |
| 금고 엔트리 | `{token, type, rule_id, rule_version, ciphertext, scope, created_at, expires_at}`. 만료된 토큰은 복원하지 않고 opaque 문자열로 안전하게 남긴다 |
| 감사 로그 | 토큰·타입·규칙ID만 기록하고 ciphertext·원문은 기록하지 않는다(FR-AU-02) |

## 3장 보완 — FR-AC-03 (CBAC 기반 동적 재식별 설계)

근거: `docs/COMPETITIVE_ANALYSIS.md` 5장 — Protecto의 CBAC(Context-Based Access
Control)가 "역할만 보고 승인 거쳐 예외 허용"하는 기존 break-glass 설계보다 앞서
있다는 격차를 확인했다. FR-AC-03을 "정적 역할 확인 후 승인 절차"에서 "역할+작업
(task)+컨텍스트를 매 요청마다 평가해 재식별 범위 자체를 동적으로 좁히는" 구조로
다시 쓴다. **티어: 유료(엔터프라이즈)** — `docs/EDITIONS.md` 4절의 경계 그대로,
단일 사용자 무료 티어에는 "누구의 역할을 누구와 비교해 판정할지"가 성립하지 않는다.

| 항목 | 규칙 |
|---|---|
| 기본값 | 모든 사용자는 토큰화(마스킹)된 뷰만 본다. 재식별(원문 열람)은 예외고, 예외의 1차 결정자는 CBAC 정책이다 — break-glass(사람 승인)는 CBAC가 거부한 경우에만 타는 2차 경로다 |
| 판정 입력(결정 벡터) | 매 재식별 요청마다 4가지를 평가한다: ① 요청자 신원·역할(FR-RB와 연동), ② 선언된 작업/목적(task — 예: "고객 결제 문의 대응", "급여 정산"), ③ 대상 데이터의 민감도 등급과 필드, ④ 요청 시점의 컨텍스트(세션 오염 상태 AG-04, 접속 위치/시간, 최근 유사 요청 빈도) |
| 판정 로직 위치 | ADR-0002의 "정책" 슬롯 — Rego(OPA)로 구현한다. 입력 4종을 OPA 정책 평가 컨텍스트로 넘기고, 출력은 `allow`(전체 재식별)·`partial`(일부 필드만, 예: 카드 뒤 4자리)·`deny`(거부 → break-glass로 전환) 3단계다 |
| 동적성 | 같은 사용자·같은 역할이라도 작업(task)이 다르면 다른 뷰를 받는다 — "역할 고정, 작업 가변"이 핵심. 역할이 바뀌지 않아도 세션이 오염됐거나(AG-04) 비정상적으로 빈번한 재식별 요청이 감지되면 같은 역할에도 더 보수적인 판정이 나온다 |
| break-glass(예외 경로) | CBAC가 `deny`한 뒤에만 진입한다. 사유 입력 필수, 2인 승인(NFR-SS-02와 연동), 시간 제한(기본 1시간) 복원, 종료 시 자동 재마스킹. 사람이 개입했다는 사실 자체를 감사 로그에 남긴다(FR-AU-02) |
| 감사 로그 | 매 판정마다 `{requester, role, task, entity_type, grade, context_signals, decision, reason_code}`를 남긴다. 원문·ciphertext는 남기지 않고, `task`는 자유 텍스트가 아니라 사전 정의된 코드값으로 제한해 간접 재식별 위험을 줄인다(FR-PV 원칙과 연동) |
| 무료 티어와의 경계 | 무료(개인) 티어는 단일 사용자라 "역할 간 차등"이 의미 없으므로 FR-AC-03 자체가 적용되지 않는다. 무료 사용자가 보는 토큰은 FR-PI-04 세션 스코프 규칙만 따른다 |

NFR-SS-05 자가 탐지는 gitleaks를 그대로 쓰고, NFR-SC-01~03 서명/SBOM은 cosign+syft/grype로 명시한다. **(수정, 8장 기술 스택 안정성 검토 참고) MCP 게이트웨이 1차 인증/allowlist를 Bifrost core가 이미 제공한다는 전제는 폐기한다** — 공식 자료 자체가 MCP gateway를 엔터프라이즈 전용으로도, OSS Advanced Features로도 서술해 경계가 불명확하기 때문이다. Cardea 코어가 MCP 1차 인증/allowlist와 "툴 호출 인자 콘텐츠 검사"를 모두 직접 구현한다. 근거: `docs/COMPETITIVE_ANALYSIS.md` 3-1장. 검증 안 된 소규모 OSS(openpii-vault, clawwarden 등)는 보안 critical 컴포넌트에 채택하지 않는다 |
| ADR-0008 | 로컬 게이트웨이/대시보드 가로채기 방식은 "클라이언트별 훅 연동"이 아니라 "표준 프로토콜(LLM API, MCP) 프록시"로 확정한다. 대시보드는 SPA가 아니라 Go 서버 렌더링(html/template) + htmx + Alpine.js + Tailwind(빌드 시 CLI로 사전 컴파일)로 구현한다 | 근거(프록시 vs 훅): 표준 프로토콜은 안정적이고 벤더 무관이라 한 번 구현하면 모든 클라이언트를 커버하지만, 도구별 훅 API는 N개 도구 = N개의 개별 유지보수 표면이고 벤더가 스펙을 바꾸면 깨진다. 네트워크 경로를 쥐고 있어야 "모델 비도달 보장"을 닫힌 집합으로 증명할 수 있고, 우회 시도도 관측 가능하다(FR-TC-01). 훅은 유출 방지의 대체재가 아니라 로컬 전용 파괴적 행동 차단 같은 보조 용도로만 쓴다. 근거(대시보드 기술): 지표·토글·탭 위주 화면은 SPA 프레임워크가 과하고, npm/Vite 빌드 체인이 기여 장벽을 높인다. `go:embed`로 HTML/CSS/JS를 바이너리에 내장해 "단일 바이너리 배포" 원칙(7장)을 그대로 지키고, 서버가 이미 들고 있는 상태(세션 오염, 예산, 모델 레지스트리)를 템플릿·SSE로 그대로 내려 상태 복제 버그를 없앤다. 더 풍부한 인터랙션이 필요해지면(시계열 차트 등) Chart.js 단일 파일 선에서 끝내고, 그 이상의 복잡한 화면(PL-01 정책 시뮬레이션, PL-05 차지백)은 cardea-enterprise 콘솔에서 별도로 다룬다(오픈코어 경계, CLAUDE.md 1장) |

## 8장 보완 — 기술 스택 안정성 검토

ADR-0001(Bifrost core 임베드)·ADR-0007(OSS 조립)이 끌어오는 외부 의존성과 7장 기술스택의
TinyGo에 대해 유지보수 상태·성숙도·장기 리스크를 검토한다. "성숙한 OSS를 쓴다"는 결정이
"리스크가 없다"는 뜻은 아니므로, 의존성별로 완화책을 명시한다.

| 구성 요소 | 상태 | 리스크 | 완화책 |
|---|---|---|---|
| Bifrost core (ADR-0001) | Apache-2.0, 활발(8,400+ 커밋, 9k+ stars, 2026-10-25 기준), 단일 스타트업(Maxim AI, 법인명 H3 Labs Inc, 2023 창업)이 단독 개발 | **공식 자료 자체가 서로 다른 말을 한다(2026-10-25 재확인, 여전히 미해결)**: GitHub README "Key Features"는 MCP를 "Advanced Features"(OSS처럼 서술)에 넣어두고, 바로 아래 "Enterprise Deployments" 섹션은 "guardrails, **MCP gateway**"를 엔터프라이즈 전용 잠금 기능으로 명시한다. 공식 AI용 정보 페이지(getmaxim.ai/llm-info)는 "Built-in MCP gateway for tool discovery and execution, with tool filtering, per-user auth"를 엔터프라이즈 Governance 절 바로 아래 "When asked about capabilities"에 적어 경계가 또 모호하다. **결론: MCP 1차 인증/allowlist를 Bifrost OSS가 책임진다고 전제하면 안 된다** | ADR-0001의 Forwarder 인터페이스로 이미 격리돼 있어 벤더 교체가 가능한 구조다. **범위를 좁힌다**: Bifrost core(`github.com/maximhq/bifrost/core`, Go SDK)는 ADR-0001 원래 목적인 "LLM 프로바이더 라우팅·폴백·스트리밍"에만 쓰고, MCP 1차 인증/allowlist는 Bifrost가 맡긴다고 전제하지 않고 Cardea 코어가 직접 구현한다(ADR-0007의 "Bifrost가 이미 제공" 전제는 폐기 — 아래 9장 미결 사항 참고) |
| Microsoft Presidio (ADR-0007) | MIT, 2026-06 Microsoft에서 독립해 커뮤니티 거버넌스(Data Privacy Stack)로 이전. 이전 후에도 활동 중(만 단위 stars, 정기 커밋) | SLA·공식 지원 없음(volunteer-run). 이전 직후 릴리스 빈도가 Microsoft 소유 시절보다 느려졌다는 평가가 있음. **(2026-10-25 실제 연동 중 확인) 공식 Docker 이미지(`mcr.microsoft.com/presidio-analyzer`)는 gRPC가 아니라 REST(Flask `/analyze`)만 제공한다** — ADR-0007·7장에 적은 "gRPC"는 Cardea 자체 ML 분류기를 위한 스택 선택이었지, Presidio라는 특정 제품의 실제 인터페이스는 아니었다(용어 정정). **추가로, 기본 이미지는 영어(en) NLP 엔진만 탑재돼 있어 한국어 요청은 거부된다**(`No matching recognizers were found`) — 한국어 지원은 별도 NLP 엔진 구성이 필요하고 아직 미착수 | ADR-0002의 "탐지기" 슬롯 뒤에 두어 교체 가능하게 유지한다. MIT 라이선스이므로 프로젝트가 정체되면 자체 포크 유지가 가능 — 이 선택지를 사전에 문서화해 둔다. REST 클라이언트(`internal/presidio`)로 실제 연동해 PERSON/EMAIL_ADDRESS 등 체크섬 없는 엔티티 탐지를 확인했다 |
| OpenBao (ADR-0007) | MPL 2.0, Linux Foundation/OpenSSF **Sandbox 단계**(최하위 성숙도 등급). 2023년 출범, 2024-09 프로덕션 2.0, 2025-06 Sandbox 편입. Nvidia·SAP·GitLab·Proton·Fermilab 등 실사용 레퍼런스 보유 | "HashiCorp/IBM 규모에는 아직 못 미침"이라는 업계 평가. 2~3년차 프로젝트로 장기 트랙 레코드가 짧음 | OpenSSF 성숙도 단계(Sandbox→Incubating→Graduated) 변화를 추적 체크포인트로 둔다. 암호화 백엔드를 Cardea 자체 매핑/스코프 로직과 분리해 둬서(FR-PI-04 설계) 필요 시 다른 크립토 백엔드로 교체 가능하게 유지한다 |
| gitleaks (ADR-0007) | MIT, 29k+ stars, 234 contributors | README에 "feature complete, 신규 기능 안 받음, 앞으로는 보안 패치만"이라고 명시된 유지보수 전용 모드. 후속 프로젝트 "Betterleaks"로 메인테이너가 이동 중이라는 신호 있음. bus factor 1(원 저자가 커밋 50%) | Cardea는 신규 기능이 아니라 안정적인 탐지만 필요하므로 유지보수 전용 모드 자체는 수용 가능. 보안 패치 공지를 추적하고, 프로젝트가 완전히 중단되면 trufflehog 또는 Betterleaks로 전환할 수 있도록 자가 탐지 호출부를 추상화해 둔다 |
| TinyGo (7장 기술스택, WASM 플러그인 컴파일) | 활발히 개선 중(릴리스당 150~240 커밋), 0.42(2026-09)에서 `recover()` 지원 등 격차 해소 진행 | 표준 라이브러리 전체 미지원, WASM에서 GC가 일반 Go보다 느림 — 실제 대상 플러그인에서 컴파일이 막힐 수 있음 | 각 Rust(WASM)/TinyGo 플러그인을 "확정"하기 전에 컴파일 스파이크(PoC)로 표준 라이브러리·reflect 제약을 먼저 검증한다. 성능이 중요한 경로는 Rust(WASM)를 우선하고, TinyGo는 제약이 적은 플러그인에 한정한다 |

## 9장 미결 사항 추가

- 지표 대시보드(PL-06)의 무료/유료 경계선 지표 목록을 운영 데이터로 재검토 (예: 무료에
  캐시 히트율까지 보여줄지, 토큰 절감량만 보여줄지)
- 지표 대시보드와 FR-PV(Cardea 자신의 개인정보 처리) 간 충돌 여부 — 보안 지표에 들어가는
  "탐지 건수"가 간접적으로 개인 행동을 추정하게 하지 않는지 법무 검토
- GW-05 "키 없는 인증"에서 개인(무료) 티어의 BYOK와 조직 SSO 전환 경계를 FR-PE-04와 어떻게
  맞출지
- GW-08 기능 인지형 fallback의 "기능 플래그 레지스트리"를 GW-04 모델 레지스트리와 통합할지,
  별도 테이블로 둘지
- 시맨틱 라우팅(GW-09)과 민감도 분류기를 같은 파이프라인에서 돌릴 때 지연(NFR-PF-01) 목표를
  어떻게 지킬지
- Bifrost core의 OSS/엔터프라이즈 기능 경계(특히 MCP Gateway·가드레일)를 벤더 공식 라이선스
  문서로 재확인 — 자료마다 서술이 달라 AG-02/03 설계가 그 경계에 잘못 의존하지 않도록 한다.
  **2026-10-25 재확인 결과: 자료마다 다른 게 아니라 벤더 공식 자료 자체가 내부적으로
  모순된다는 걸 확인했다(8장 기술 스택 안정성 검토 표 참고) — 따라서 AG-02/03의 MCP
  1차 인증/allowlist는 Bifrost가 제공한다고 전제하지 않고 Cardea가 직접 구현하는 쪽으로
  ADR-0007을 수정했다. 남은 일: 실제로 Bifrost OSS 바이너리를 설치해 MCP 엔드포인트가
  라이선스 키 없이 동작하는지 직접 확인(문서 비교만으로는 한계가 있다)**
- OpenBao의 OpenSSF 성숙도 단계(Sandbox→Incubating→Graduated) 변화를 추적할 체크포인트를
  정하고, 단계가 정체되면 토큰 금고 크립토 백엔드 재검토 트리거로 쓴다
- Rust(WASM)/TinyGo로 배정하기 전에 실제 대상 플러그인으로 컴파일 스파이크(PoC)를 돌려
  TinyGo의 표준 라이브러리·reflect 제약이 막히지 않는지 먼저 검증한다

## 10장 신설 — Getting Started 온보딩 UX를 수용 기준에 반영

근거: `docs/GETTING_STARTED.md` 초안·개정 과정에서 발견한 사용성 문제 6개(상세는
`docs/history/GETTING_STARTED.md` 참고)를 실제 FR/AG 수용 기준으로 못박는다 — 문서만
고치고 요구사항에 반영하지 않으면 구현 단계에서 다시 흩어진다. 기존 ID의 수용 기준을
확장하는 것이므로 새 ID는 만들지 않는다(설치 플랫폼 분기는 수용 기준이 아니라 순수
문서·패키징 편의라 ID를 만들지 않는다).

| ID | 추가 수용 기준 |
|---|---|
| AG-12 | ① `cardea quickstart <tool>`로 감지·설치·연결·검증을 한 명령으로 묶는다(기존 "환경변수 교체만으로 연결"을 원스텝 CLI로 감싼 것, 수동 환경변수 교체는 하위 경로로 유지). ② `cardea connect --show-changes`로 현재 연결된 도구·변경된 환경변수·설정 파일을 사용자가 확인할 수 있어야 한다. ③ `cardea disconnect <tool>`로 ②에서 바뀐 항목을 전부 원상복구해야 한다(수동으로 되돌릴 필요가 없어야 함) |
| FR-PI-05 | 전송 전 미리보기(마스킹될 토큰을 실제 전송 전에 보여주는 기능)는 대화형 CLI 세션에서만 기본 노출한다. 비대화형 경로(스크립트, CI, 백그라운드 데몬)에서는 매 요청마다 미리보기를 막지 않고 기본적으로 건너뛴다 — 끄지 않으면 자동화 파이프라인이 멈추기 때문이다. 옵트인 플래그(`--preview`)로 비대화형 경로에서도 켤 수 있게 하되 기본값은 꺼짐이다 |
| AG-04, AG-09 | 에이전트 거버넌스 화면은 2단으로 노출한다 — 기본 화면: 세션 오염 배지(AG-04), 예산 + 즉시 중지(AG-09) 2개만 먼저 보여준다. 고급 설정(세부 임계값, 알림 채널, MCP 프록시 상세, 사용자 프로필 통제)은 별도 메뉴/플래그 뒤에 둔다. 처음 쓰는 사람이 한 화면에서 6개 항목을 동시에 이해하도록 요구하지 않는다 |
| FR-RP-02, FR-EXT-02 | 서명 검증 실패로 플러그인/룰팩을 거부할 때(fail-closed), 사용자에게 보여줄 메시지는 최소 3가지를 포함해야 한다: (a) 실패 사유 코드(서명 없음/서명 불일치/신뢰 체인 만료 등), (b) 지금 적용 중인 건 이전 정상 버전이라는 안내, (c) 상세 확인 명령(`cardea verify <plugin>` 등). "검증 실패"라고만 띄우고 끝내지 않는다 |
