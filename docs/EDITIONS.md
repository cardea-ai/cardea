# Cardea 에디션 — cardea (오픈코어) vs cardea-enterprise (상용)

ADR-0005 기준: Apache-2.0 코어(`cardea`, 이 저장소)와 상용 확장(`cardea-enterprise`,
비공개 저장소)을 분리한다. 같은 바이너리에 라이선스 키로 유료 기능을 연다. 코어의 탐지
품질은 두 에디션이 동일하다 — 유료는 "더 잘 탐지"가 아니라 "조직 단위로 통제·기록·연동·
가시화"하는 기능이다. 두 표는 같은 카테고리 순서로 정렬했으니 같은 행끼리 비교하면 된다.

## 카테고리별 비교

| 전송 전 미리보기/예외 지정 (FR-PI-05) | 조직 사전 |
| 첨부파일 검사 (FR-PI-03) | |
| 응답·툴 출력 검사 (FR-PI-09) | |

### 10. 지표 대시보드 (PL-06) — 비용 · 보안 · 효율성

같은 세 카테고리를 보여주지만, 무료는 "본인 단위" 지표만, 유료는 "조직 단위" 전체 지표를
본다. 무료 화면에서 유료 전용 지표는 잠금 표시로 안내한다.

| 카테고리 | cardea (무료) — 본인 단위만 | cardea-enterprise (유료) — 조직 단위 전체 |
|---|---|---|
| 비용 | 본인 토큰·API 사용량, 모델별 추정 비용 (FR-PE-03) | 부서·팀·프로젝트별 비용 배분(차지백) (PL-05), 예산 대비 소진율, 모델/라우팅 비용 비교 |
| 보안 | 본인 탐지·차단 건수 합계 (유형 구분 없음) | 등급별/유형별 탐지 현황, 오탐률, 우회 트래픽 현황 (FR-BY-01), ISMS-P 증적 리포트, SIEM 전달 상태 (FR-AU-05) |
| 효율성 | 캐시 히트율, 토큰 절감량 — 개인 (FR-TK-06) | 캐시 히트율·토큰 절감량(팀 공유 포함), 게이트웨이 지연 p95 (NFR-PF-01,02), 가용성·장애 전환 현황 (NFR-AV-01), 외부 API 환산 비용 대비 자체 서빙(GPU) 비용 리포트 |

지표의 데이터 소스는 OpenTelemetry 메트릭/감사 로그 집계이며, 두 에디션 모두 원문이나
타인의 식별 데이터를 지표에 노출하지 않는다(NFR-OB-02).

### 11. 게이트웨이 코어 (프로토콜·어댑터·레지스트리)

근거: 당근마켓 「당근은 왜 LLM Router를 직접 만들었을까?」 — 사내 라우터 구축 교훈을
게이트웨이 코어 요구사항으로 흡수했다(GW-01~09). 탐지 품질처럼 코어 전달 구조도 두
에디션이 동일하며, 차이는 운영 규모 기능(팀 알림, 키 단위 예산, 멀티벤더 자동 전환)뿐이다.

| cardea (무료) | cardea-enterprise (유료) |
|---|---|
| 듀얼 프로토콜 — OpenAI(Chat/Responses/Embeddings) + Anthropic Messages (GW-01) | 팀 단위 장애 알림 (GW-07) |
| SDK 기반 프로바이더 어댑터(단순 프록시 아님), 플러그인 인터페이스 (GW-02) | 기능 인지형 fallback·멀티벤더 라우팅 (GW-08) |
| 프로토콜 확장 규약 `cardea.*` (GW-03) | 키(서비스 계정) 단위 월 예산 |
| 선언적 모델 레지스트리 + 핫 리로드 (GW-04) | 시맨틱·비용 라우팅 (GW-09) |
| 키 없는 인증(BYOK 로컬 키체인) (GW-05) | |
| 사용량·비용 계측(프롬프트/완료/캐시 토큰) (GW-06) | |
| 기본 관측 지표(RPS/지연/에러율) (GW-07 기본) | |

## 경계 판단 규칙 (헷갈릴 때)

1. "개인이 혼자 써도 가치가 있는가" → 그렇다면 cardea.
2. "조직이 여러 사용자/팀에 걸쳐 정책을 강제하거나, 장기 보관·규제 증적·SSO 같은 조직
   운영 기능인가" → 그렇다면 cardea-enterprise.
3. 탐지 정확도·차단 자체, 그리고 지표 집계 로직 자체는 절대 에디션으로 가르지 않는다.
   가르는 것은 "범위(본인 vs 조직)"와 "보존·공유·연동 여부"뿐이다. 라이선스가 만료돼도
   탐지·차단은 유지되고, 관리 기능과 조직 단위 지표만 읽기 전용/잠금으로 바뀐다(FR-LC-02).
