# Cardea 사용 가이드 (예상 Getting Started, 구현 전 UX 드래프트)

상태: 초안. 변경 이력은 `docs/history/GETTING_STARTED.md`에서 관리한다.

## 이 문서의 목적

아직 Cardea 코드는 없다(`go.mod`만 존재). 이 문서는 **구현을 시작하기 전에** "처음 쓰는
사용자가 각 기능에 실제로 어떻게 접근하는가"를 먼저 글로 그려보고, 그 과정에서 사용성
문제·누락·과한 단계를 찾아내는 것이 목적이다. 여기 적힌 명령어(`cardea ...`)와 화면
구성은 아직 확정된 스펙이 아니라 **검증용 가설**이다 — 실제 구현 시 바뀔 수 있다.

범위는 `docs/EDITIONS.md`의 **cardea(무료) 티어**만 다룬다. 조직 단위 기능(SSO, 팀
메모리 거버넌스, 장기 감사 등)은 cardea-enterprise이며 이 문서의 대상이 아니다.

가정하는 사용자: 보안팀 승인 없이 혼자 먼저 써보는 개발자(`docs/POSITIONING.md`의 1차
ICP). 코딩 에이전트(Claude Code 등)를 이미 쓰고 있고, 사내 정보가 외부 모델로 샐까
걱정돼서 Cardea를 찾아본 상태라고 가정한다.

> 이 버전은 1차 드래프트에서 발견한 사용성 문제 6개(퀵스타트 원스텝화, 연결 가시성·
> 되돌리기, 미리보기 범위 제한, 에이전트 거버넌스 단계적 노출, 서명 실패 사유 설명,
> 설치 플랫폼 분기)를 아래 흐름에 직접 반영한 개정판이다. 무엇이 왜 바뀌었는지는
> `docs/history/GETTING_STARTED.md`에 있다.

## 0단계 — 설치 (목표: 1분)

**접근 경로**: README 또는 설치 페이지에 있는 플랫폼별 설치 명령.

```bash
# macOS / Linux / WSL
curl -fsSL https://get.cardea.dev/install.sh | sh

# Windows (PowerShell, WSL이 아닌 네이티브 환경)
irm https://get.cardea.dev/install.ps1 | iex
```

설치 스크립트는 OS·쉘을 감지해 알아서 분기한다 — 사용자가 "나는 WSL인지 네이티브
Windows인지"를 직접 판단할 필요가 없도록, 설치 페이지에는 두 명령을 나란히 보여주고
감지에 실패하면(예: WSL인데 `uname`이 막힌 환경) 둘 다 시도해보라는 안내를 붙인다.

단일 바이너리(Go)라 별도 런타임 설치가 없다. 설치가 끝나면 터미널에 **다음 할 일을
바로** 보여준다(사용자가 README로 돌아가지 않아도 되게):

```
Cardea v0.1.0 installed → /usr/local/bin/cardea
다음 실행: cardea quickstart
```

## 1단계 — 퀵스타트: 설치부터 연결까지 한 명령 (목표: 30초)

이전 드래프트는 `cardea init` → `cardea connect <tool>` 두 명령으로 나뉘어 있었다.
NoPII 같은 경쟁 제품은 "SDK의 `base_url` 한 줄 교체"가 전부라, 이 2단계 구조는 그보다
느리다는 게 1차 드래프트의 핵심 발견이었다. 이번 개정에서는 **원스텝 경로를 기본값**으로
올린다.

**접근 경로**: 설치 후 안내된 명령 그대로 실행하되, 쓰는 도구를 바로 지정한다.

```bash
cardea quickstart claude-code
```

이 한 명령이 안전한 기본값으로 다음을 전부 처리한다(질문 없이):

1. 로컬 포트에 Cardea 실행 + 토큰 금고 암호화 키 생성
2. 기본 민감정보 탐지 룰팩 설치(FR-PI-01,02,08,11 — 한국 민감정보 유형 포함)
3. 등급 구분 없이 단일 모델로 라우팅(세분화는 나중에 `cardea policy`로)
4. Claude Code 연결(2단계 참고)

완료 후 출력:

```
✓ Cardea가 로컬에서 실행 중입니다 (http://localhost:8787)
  — 이제부터 이 포트를 거친 요청만 모델에 전달되기 전에 검사됩니다.
✓ 기본 민감정보 탐지 룰팩 설치됨
✓ Claude Code 연결됨 (바꾼 내용: 2단계 참고 — cardea connect --show-changes)
세부 설정이 필요하면: cardea init  (등급별 모델, 룰팩 선택 등 고급 설정 마법사)
```

도구를 아직 안 정했거나 세부 설정을 먼저 보고 싶은 사용자를 위해 **기존 2단계 경로도
그대로 유지**한다 — `cardea init`(대화형 마법사, 질문 3개 + 자동 처리)과
`cardea connect <tool>`을 따로 실행할 수 있다. 다만 설치 완료 메시지와 README 모두
`quickstart`를 1번으로 보여준다.

**사용성 체크포인트**
- `quickstart`가 "질문 없이" 넘어가는 대신, 끝난 뒤 "바꾼 설정을 다시 보려면/고치려면"
  경로를 반드시 같이 보여줘야 한다(위 출력의 `cardea connect --show-changes`,
  `cardea init`) — 자동화와 투명성을 동시에 만족시키는 지점이다.

## 2단계 — 에이전트 연결 상세: 무엇이 바뀌었는지 보기, 되돌리기

**접근 경로**: 1단계에서 자동으로 처리됐지만, 변경 내역 확인과 되돌리기는 항상 가능해야
한다.

```bash
cardea connect --show-changes claude-code
```

```
변경됨:
  ANTHROPIC_BASE_URL → http://localhost:8787/anthropic
  파일: ~/.claude/settings.json (백업: ~/.cardea/backups/settings.json.2026-10-25)
  쉘 프로필: 변경 없음 (settings.json 방식 사용)
되돌리려면: cardea disconnect claude-code
```

여러 쉘·여러 터미널 창을 쓰는 경우를 위해, 환경변수 방식으로 연결했다면 완료 메시지에
"새 터미널을 열거나 `source ~/.zshrc`를 실행하세요"를 반드시 포함한다.

다른 도구(Cursor, Codex CLI)도 같은 패턴(`OPENAI_BASE_URL` 교체 + `--show-changes` +
`disconnect`)으로 동작해, 어떤 도구를 연결하든 같은 방식으로 확인/되돌리기가 된다.

**사용성 체크포인트**
- "자동으로 설정 파일을 고쳐준다"는 편의와 "뭐가 바뀌었는지 모르고 넘어가면 나중에
  디버깅이 어렵다"는 우려를 `--show-changes`로 동시에 해결한다. 이 명령은 연결 직후
  뿐 아니라 언제든 다시 실행 가능해야 한다(설정을 까먹었을 때 재확인용).

## 3단계 — 첫 민감정보 마스킹 체감 (FR-PI 전반) (목표: 1분)

**접근 경로**: 연결 후 평소처럼 코딩 에이전트에 민감정보가 섞인 프롬프트를 보낸다.
별도 명령 없음 — 기능이 "보이는" 시점이 바로 이 단계다.

예: Claude Code에 다음과 같이 요청한다.

```
이 로그에서 에러 찾아줘:
2026-10-25 user=김민준 rrn=901231-1234567 card=4111-1111-1111-1111 에러: timeout
```

모델에게는 이렇게 도달한다(터미널에는 평소와 동일하게 응답만 보이지만, **최초 1회만**
안내 배너를 보여준다):

```
[Cardea] 3건 마스킹 → 모델 전송, 응답에서 자동 복원됨 (상세: cardea log --last)
         (이 안내는 처음 한 번만 표시됩니다. 항상 보려면: cardea verbose on)
```

모델의 응답이 돌아올 때 토큰은 자동으로 원문으로 복원돼 사용자 화면에는 다시
"김민준", 실제 주민번호 끝자리 등으로 보인다(FR-PI-04 가역 마스킹).

**전송 전 미리보기(FR-PI-05)는 기본적으로 꺼져 있다.** 코딩 에이전트처럼 비대화형·
자동화된 흐름에서 매 요청마다 "전송해도 될까요?"를 띄우면 에이전트 루프가 막히기
때문이다. 기본 동작은 **항상 자동 마스킹 후 즉시 전송**이고, 확인은 사후에
`cardea log --review`로 한다. 미리보기 자체가 필요한 경우(한 번에 뭐가 나가는지
눈으로 보고 승인하고 싶을 때)에는 대화형 CLI에서만 옵트인으로 켠다:

```bash
cardea chat --preview-before-send   # 대화형 CLI 전용, 코딩 에이전트 자동화 흐름에는 적용 안 됨
```

첨부파일 검사(FR-PI-03)는 "채팅창에 붙여넣은 파일"과 "에이전트가 툴로 읽어 컨텍스트에
넣은 파일" 양쪽을 모두 검사 대상으로 포함한다 — 한쪽만 되면 체감 범위가 좁아 보이므로
둘 다 같은 경로(FR-PI-09 응답·툴 출력 검사와 동일한 가로채기 지점)를 탄다.

## 4단계 — 라우팅 규칙 확인·개인 규칙 설정 (FR-RT) (목표: 1분, 건너뛰기 가능)

**접근 경로**: CLI 명령 또는 로컬 대시보드(`cardea dashboard` → 브라우저 자동 열림).

```bash
cardea policy show        # 지금 적용 중인 등급별 라우팅 규칙을 표로 출력
cardea policy set --grade confidential --model claude-opus --provider anthropic-zdr
```

CLI로 등급·모델·프로바이더 이름을 다 외우기 어려운 사용자를 위해, 같은 설정을 로컬
대시보드에서 드롭다운으로도 제공한다 — CLI/GUI 중 편한 쪽을 쓰면 된다.

등급 비강하 폴백(FR-RT-03,04)이 작동해 다른 모델로 전환될 때는 조용히 넘어가지 않고
`cardea log`에 전환 이유를 남긴다(예: "claude-opus 장애 → claude-sonnet으로 전환,
등급 동일 유지").

## 5단계 — 메모리·에이전트 거버넌스 (FR-MEM-03, AG-02/04/08/09)

AG 범주는 기능이 6개로 많아, 전부 한 화면에 몰아넣으면 "에이전트 거버넌스"가 뭔지도
모르는 신규 사용자가 압도된다. 그래서 **기본 화면에는 2개만 보이고, 나머지는 "고급
설정"으로 접는다(progressive disclosure).**

### 기본 화면(대시보드 "에이전트" 탭을 열면 바로 보임)

- **세션 오염 추적(AG-04)**: 세션이 민감 데이터를 읽은 뒤의 상태를 배지로 표시
  (`🔶 이 세션은 기밀 데이터를 읽었습니다`) — 사용자가 조회하지 않아도 보이는 게
  핵심이다.
- **예산 + 즉시 중지(AG-09)**: `cardea budget set --daily 5000`으로 토큰/비용 예산을
  걸고, 초과 시 터미널 경고 + CLI와 데스크톱 트레이 아이콘 양쪽에서 누를 수 있는
  **큰 "즉시 중지" 버튼/명령**(`cardea stop`)을 둔다. 긴급 상황엔 한 번에 눌리는 게
  중요하다.

### "고급 설정"을 펼쳤을 때 보이는 나머지 4개

- **로컬 메모리 쓰기 전 검사(FR-MEM-03)**: 자동 동작, 켤 필요 없음. 차단 시
  `cardea log --type memory`에서 사유 확인.
- **기본 MCP 프록시(AG-02 기본)**: `cardea connect --mcp`로 기존 MCP 서버 설정 앞에
  자동 삽입, 툴 호출 인자가 검사됨.
- **사용자 프로필 통제(AG-08)**: "이 프로필에서 쓸 수 있는 모델/등급" 스위치.
- 위 두 가지(세션 오염 배지, 예산)의 세부 임계값·알림 채널 설정.

## 6단계 — 토큰/캐시 절약 확인 (FR-TK-01,02,03,05,06) (목표: 30초, 건너뛰기 가능)

**접근 경로**: 자동 동작, 확인은 `cardea stats` 또는 대시보드 "효율성" 탭.

```bash
cardea stats
```

```
오늘 절약: 캐시 히트 42%, 토큰 절감 약 18,000 tok (추정 $0.27)
보안: 캐시에는 마스킹본만 저장됩니다 — 원문이 캐시에 남지 않습니다 (FR-TK-05)
```

효율성 숫자와 보안 이점(캐시 원문 금지)을 같은 화면에 함께 보여줘서, "빠르고
저렴하다"와 "안전하다"를 분리된 메시지가 아니라 하나로 전달한다
(`docs/POSITIONING.md`의 "탐지 숫자로 안 싸운다" 원칙과 일치).

## 7단계 — 게이트웨이 코어 둘러보기 (GW-01~07) (선택, 목표: 1분)

**접근 경로**: 이미 1단계에서 동작 중 — 이 단계는 "있는지 몰랐던" 기능을 발견하는
탐색용.

```bash
cardea models list          # 선언적 모델 레지스트리 (GW-04)
cardea models add my-vllm --base-url http://localhost:11434/v1   # 핫 리로드, 재시작 불필요
```

모델을 추가한 직후 재시작 안내는 전혀 없어야 한다(안내가 뜨면 "핫 리로드"라는 주장과
모순돼 신뢰가 깎인다).

기본 관측 지표(GW-07)는 1인 사용자에겐 "RPS, p99 지연" 같은 운영 용어가 낯설다 —
개인 티어 화면에서는 운영 지표 용어 대신 사용자 언어로 보여준다:

```bash
cardea stats --health
```

```
최근 24시간: 느려진 요청 없음. 평균 응답 지연 1.2초.
```

## 8단계 — 룰팩·플러그인 관리 (FR-RP-01,02, FR-EXT-01~05) (선택, 목표: 1분)

**접근 경로**: `cardea rulepacks` / `cardea plugins`

```bash
cardea rulepacks list        # 설치된 룰팩과 버전, 자동 갱신 여부
cardea plugins install korean-biz-regno    # 서명 검증 후 설치, 실패 시 이전 버전 유지
```

서명 검증에 실패하면 **조용히 거부하지 않고, 왜 거부했는지와 어떤 상태로 남았는지를
명확히 출력한다**(fail-closed가 CLAUDE.md의 기본값이지만, 사용자에게는 "설치가 안
됐나?"로 보이면 신뢰가 깎이기 때문이다):

```
✗ korean-biz-regno v1.3.0 서명 검증 실패 — 신뢰할 수 없는 서명자
  → 안전을 위해 이전 버전(v1.2.0)을 계속 사용합니다. 탐지 기능은 중단되지 않았습니다.
  자세히: cardea plugins verify korean-biz-regno --explain
```

## 9단계 — 트래픽 수집/우회 방지 체크 (FR-TC-01, FR-PE-01~04) (선택)

**접근 경로**: `cardea doctor` 가 "이 기기에서 Cardea를 거치지 않는 AI 트래픽이
있는지"를 점검해 알려준다.

```bash
cardea doctor
```

```
⚠ 브라우저에서 ChatGPT 웹을 직접 쓰고 있습니다 (Cardea 미경유)
  → 브라우저 확장 설치: cardea browser-extension install
✓ 로컬 에이전트 프록시 정상 동작 중
✓ BYOK 키체인 확인됨
```

"미경유 트래픽 발견"은 경고로만 띄우고 차단하지 않는다(무료 티어는 가시화, 강제 차단은
엔터프라이즈 FR-BY-01 영역) — 이 경계를 화면 문구로 분명히 해서 "왜 안 막냐"는 혼란과
"감시당하나"는 오해를 둘 다 피한다.

## 10단계 — 개인 지표 대시보드 (PL-06 무료 라인, FR-PE-03)

**접근 경로**: `cardea dashboard` → 기본 브라우저로 로컬 대시보드 열림(설치 1회 이후
언제든).

화면 구성(본인 단위만, EDITIONS.md 10절):
- 비용: 토큰·API 사용량, 모델별 추정 비용
- 보안: 탐지·차단 건수 합계(유형 구분 없음 — 유형별 분석은 유료)
- 효율성: 캐시 히트율, 토큰 절감량

유형별 상세는 잠겨 있지만, 잠긴 영역에는 "업그레이드하세요" 버튼 대신 **흐린 미리보기
+ "이게 켜지면 등급별/유형별 탐지 현황, 오탐률까지 보입니다" 설명**을 보여준다 — 막연한
업셀 버튼보다 구체적인 설명이 전환 유도에 낫다.

## NoPII 온보딩과의 비교 체크 (갱신)

NoPII는 "SDK의 `base_url` 한 줄 교체"가 전부다(`docs/COMPETITIVE_ANALYSIS.md` 5장).
`cardea quickstart <tool>` 한 명령으로 합친 뒤 격차를 다시 보면:

- 설치(0단계)는 Cardea가 로컬 바이너리라서 여전히 NoPII(가입만 하면 되는 SaaS)보다
  한 단계 많다 — 이 부분은 구조적 차이라 줄일 수 없다. 설치 스크립트 자체를 플랫폼
  감지까지 포함해 "복붙 한 줄"로 유지하는 게 최선이다.
- 연결(1단계)은 이제 명령 1개로 NoPII의 "`base_url` 수정 1곳"과 단계 수가 같아졌다.
- NoPII에는 없는 것(오픈코어 무료 영구, 클라우드 비의존, 통합 정책 엔진)은 3·5단계에서
  체감되므로, 남은 유일한 격차(설치 1단계)를 상쇄할 만큼 3단계의 신뢰 신호가 중요하다.

## 검증 필요 사항 (구현 시 확인)

1차 드래프트에서 발견한 문제는 위 흐름에 반영했다. 구현 단계에서 실제로 확인해야 할
것들만 남긴다.

- 설치 스크립트의 OS/쉘 자동 감지가 실패하는 실제 사례(예: WSL인데 `uname` 접근이
  막힌 보안 정책 환경)가 얼마나 되는지 파악하고, 감지 실패 시 안내 문구를 다듬는다.
- `cardea quickstart`가 "질문 없이" 전부 처리하는 게 맞는지, 최소 1개(어떤 도구를
  쓰는지)는 명령 인자로 받게 할지 베타 사용자 테스트로 확인한다.
- 대시보드의 "에이전트" 탭 기본/고급 분리가 실제로 신규 사용자의 인지 부하를
  줄이는지 사용성 테스트로 검증한다.
